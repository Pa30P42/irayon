# Этап 1 — чек-лист ручного QA

## Что этот список покрывает, а что нет

Серверная логика уже отработана: 278 автоматических тестов плюс живой прогон API по
реальной базе (авторизация, отзыв сессий, гейт регистрации хостов, применение
изменений «вживую» против отложенных правок, машина состояний фото, вырезание EXIF,
одобрение/отклонение).

**Чего никогда не открывали в браузере — это UI.** Формы, загрузчик изображений,
вёрстка страницы модерации, три локали и мобильные ширины. Риск именно там, поэтому
на этом список и сосредоточен.

## Подготовка

```bash
pnpm dev          # http://localhost:3000
```

Учётные записи, уже заведённые в базе (вход на `/az/signin` — форма по email только
для dev; пароля нет, и кнопки Google нет, потому что OAuth ещё не подключён):

| Email                  | Роль                 | Примечания                                          |
| ---------------------- | -------------------- | --------------------------------------------------- |
| `hajiev93@gmail.com`   | админ + хост         | владеет 13 каталожными объявлениями                 |
| `testhost@example.com` | хост                 | владеет `test-host-cabin`, в списке разрешённых     |
| `guest@example.com`    | обычный пользователь | **не** в списке разрешённых — для негативных тестов |

Любой другой введённый email создаёт нового пользователя вне списка разрешённых —
это бывает полезно.

Держите терминал с `pnpm dev` на виду — письма печатаются там строками
`email_logged` вместо отправки.

## A. Публичный сайт — регрессия

Здесь ничего не должно было измениться, кроме звёзд. Если что-то ещё выглядит иначе —
это баг.

- [ ] `/` редиректит на `/az`
- [ ] Главная: рекомендуемые объявления, сетка регионов, тизер карты — всё отрисовывается
- [ ] `/az/listings` — фильтры, переключатель карты, сортировка, бесконечная прокрутка
      по-прежнему работают
- [ ] `/az/listings/[slug]` — галерея, удобства, карта, карточка бронирования, кнопка звонка
- [ ] Переключатель языка оставляет вас на той же странице в `ru` и `en`
- [ ] `/robots.txt` и `/sitemap/listings.xml` по-прежнему отвечают

**Новое поведение — фейковые рейтинги скрыты:**

- [ ] Засеянные объявления (`reviewCount > 0`) по-прежнему показывают звезду и оценку
- [ ] `test-host-cabin` (`reviewCount === 0`) **нигде не показывает звезду** — ни на
      карточке каталога, ни в строке списка, ни в шапке детальной страницы
- [ ] Шапка детальной страницы по-прежнему показывает адрес, когда звезда скрыта
      (без осиротевшей `·`)

## B. Авторизация

- [ ] Без входа: в шапке кнопка **Войти**
- [ ] `/az/signin` показывает только dev-форму. Ни кнопки Google, ни падения
- [ ] Войдите как `hajiev93@gmail.com` → в шапке ваше имя, выпадающее меню открывается
- [ ] В меню есть: Мои бронирования, Настройки, Кабинет хоста, **Админ-панель**, Выйти
- [ ] Выход возвращает шапку в состояние «не вошёл»
- [ ] Войдите как `guest@example.com` → в меню **нет** пункта «Админ-панель»
- [ ] Зайдите на `/az/host` без входа → редирект на `/az/signin?next=/az/host`
- [ ] Войдите оттуда → вы попадаете обратно на `/az/host`, а не на главную
- [ ] `/az/signin` при уже выполненном входе → вас отбрасывает прочь

относятся к этапам 2 и 3. Ссылки есть, потому что меню собирается один раз.

## C. Админ-панель — регрессия

Вся панель переехала со старого HMAC-логина на сессии Google/dev, и все 15 файлов
роутов были переписаны. Этот раздел — самый ценный регрессионный проход в списке.

- [ ] `/admin/listings` — список, поиск, фильтр по статусу, счётчики фото
- [ ] `/admin/listings/new` — отрисовываются все секции; работает выбор точки на карте;
      работают вкладки локалей
- [ ] Создайте объявление с 2–3 фото → оно сохраняется и появляется в списке
- [ ] **URL загруженного изображения заканчивается на `.webp`** (проверьте `src`
      галереи в devtools) — каждая загрузка теперь перекодируется на сервере
- [ ] Редактирование объявления: сетка существующих изображений отображается, стрелки
      перестановки работают, «сделать обложкой» работает, удаление отдельного
      изображения работает
- [ ] Удалите объявление
- [ ] Регионы: создание, редактирование, загрузка обложки, удаление
- [ ] Сёла: создание, переименование, удаление
- [ ] Удобства: создание, редактирование, удаление
- [ ] `/admin/logs` — свежие записи теперь несут **id админа** вместо null
- [ ] Выход изнутри `/admin` работает и приводит вас на страницу входа

## D. Кабинет хоста

Войдите как `testhost@example.com`.

- [ ] `/az/host` — четыре счётчика, и числа выглядят правильно
- [ ] `/az/host/listings` — `test-host-cabin` в списке с бейджем **Одобрено**
- [ ] `/az/host/listings/new` — форма побайтово совпадает с админской
- [ ] Создайте объявление с фото → попадает в ваш кабинет с бейджем **На проверке**
- [ ] Этого объявления **нет** на `/az/listings`, а его детальный URL даёт 404
- [ ] Отредактируйте **цену** одобренного объявления → сохраняется, баннера о проверке
      нет, новая цена сразу в эфире
- [ ] Отредактируйте его **телефон** или **заголовок** → кабинет показывает «изменения
      на проверке», а публичная страница по-прежнему показывает СТАРОЕ значение
- [ ] Загрузите фото к одобренному объявлению → появляется в вашей сетке, но **не** на
      публичной странице
- [ ] Попробуйте удалить последнее оставшееся живое фото → отказ с сообщением о
      минимальном количестве фото
- [ ] Навигация хоста корректно подсвечивает текущий раздел

Теперь войдите как `guest@example.com`:

- [ ] В меню есть **Стать хостом** → `/az/host/start`
- [ ] Эта страница показывает «регистрация закрыта» и **не** показывает кнопку создания
- [ ] Ввод `/az/host/listings/new` напрямую отбрасывает вас обратно на `/az/host/start`

## E. Модерация

Войдите как `hajiev93@gmail.com`, откройте `/admin/moderation`.

- [ ] В очереди есть созданное в разделе D объявление, ожидающие — сначала самые старые
- [ ] **Новое** объявление не показывает таблицу различий (сравнивать не с чем)
- [ ] **Отредактированное** объявление показывает таблицу различий: колонки _Живое_ и
      _Предложенное_, только для полей, которые действительно изменились
- [ ] Лента фото показывает бейджи на фотографиях, которые добавляются или удаляются
- [ ] Нажмите **Отклонить** → появляется поле причины; кнопка отправки остаётся
      неактивной, пока вы не наберёте 10 символов
- [ ] Отклоните с настоящей причиной → элемент уходит из очереди
- [ ] Войдите как этот хост → причина отклонения видна на `/az/host/listings` и на
      странице редактирования
- [ ] Снова под админом **Одобрите** ожидающее объявление → оно появляется на публичном
      сайте, а любое ожидающее фото становится видимым
- [ ] Одобрение объявления, все фото которого помечены на удаление → показывает
      _«Нельзя одобрить: объявление осталось бы без фотографий. Отклоните вместо
      этого.»_
- [ ] В терминале напечатались строки `"type":"email_logged"` с
      `listing-approved` / `listing-rejected` и адресом хоста

## F. Локализация

Переключитесь на `ru` и `en` и заново откройте каждую новую поверхность. Вы ищете
протекающие сырые ключи вроде `host.dashboard.title` и текст, вылезающий за контейнер.

- [ ] `/{locale}/signin`
- [ ] `/{locale}/host` и `/{locale}/host/listings`
- [ ] `/{locale}/host/start`
- [ ] `/admin/moderation` (использует админский переключатель локали, а не URL)

## G. Точечные проверки безопасности

Быстро, и каждая закрывает то, что реально было сломано или недавно добавлено.

- [ ] `/admin/x.y` → редирект на вход. **Раньше это отрисовывалось** — любой путь с
      точкой полностью обходил гейт
- [ ] Скопируйте URL редактирования чужого объявления (`/az/host/listings/<id>/edit`)
      и откройте его как `guest@example.com` → **404**, а не 403. 403 подтвердил бы,
      что id настоящий
- [ ] Devtools → Network → любой ответ `/api/admin/*` → заголовок
      `cache-control: private, no-store`
- [ ] Войдите как `guest@example.com`, зайдите на `/admin` → 404, а не форма входа

## Пока вне области действия

Это этапы 2 и 3, они дадут 404 или будут отсутствовать:

- `/{locale}/account/*` (бронирования, настройки)
- Заявки на бронирование — карточка бронирования пока лишь калькулятор цены плюс
  ссылка на телефон
- Сообщения, уведомления, жалобы, `/admin/users`
- Настоящие письма (драйвер — `log`), устойчивое ограничение частоты (сейчас в
  памяти), вход через Google

## Если хотите начать с чистого листа

```bash
pnpm prisma:reset   # СНОСИТ ВСЁ, заново прогоняет все 6 миграций, заново засевает
pnpm prisma:seed
```

Сид создаёт учётную запись хоста-заглушки (`catalogue@irayon.invalid`), чтобы она
владела каталогом, потому что `hostId` обязателен, а никто ещё не входил. Затем:

1. войдите один раз как `hajiev93@gmail.com`
2. `pnpm backfill:admin-host` — повышает вас до админа, переносит каталог на вашу
   учётную запись, удаляет заглушку и поднимает версию вашей сессии
3. следующий запрос выкинет вас из сессии — **так и задумано**; войдите снова и
   вернётесь уже с админским токеном
